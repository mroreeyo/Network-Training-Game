## 2. 검수 체크리스트 결과

PC는 1280px 폭, 휴대폰은 360×740px 화면으로 확인했습니다. 시안은 움직이지 않는 정적 화면이라서, 동작이 필요한 항목은 "1단계에서 확인"으로 남겼습니다.

| 항목 | 결과 | 근거 |
| --- | --- | --- |
| 게임 이름을 가려도 다른 학습 앱과 구별된다 | 통과 (작성자 판단, 확인 필요) | 컨베이어 한 줄 안내도, 운송장 모양 라벨, 기운 도장이 화면마다 반복됩니다. 최종 판단은 직접 보고 내려 주세요. |
| 가장 먼저 눈에 들어오는 것이 게임판이다 | PC 통과, **휴대폰 미흡** | 휴대폰 첫 화면에서는 작업 지시서와 부품 트레이가 대부분을 차지하고, 게임판은 위쪽 약 130px만 보입니다 (4절 결정 사항 A). |
| 금지 목록에 해당하는 요소가 없다 | 통과 | CSS와 HTML을 검색한 결과 그라데이션, 그림자, 흐림 효과, 이모지, 화살표 문자가 없습니다. 등장 효과와 마우스 올림 확대도 쓰지 않았습니다. |
| 토큰 파일에 없는 색, 간격, 글꼴 값이 없다 | 통과 (예외 3종 기록) | 색상 코드는 0건입니다. px 값은 화면 폭 조건(`@media`) 2곳에만 있습니다. 예외는 3절에 적었습니다. |
| 접근성 기준 6개 | 4개 통과, 2개는 1단계에서 확인 | 아래 표 참고 |
| 휴대폰(360px)에서 가로 스크롤이 없다 | 통과 | 4개 화면 모두 문서 폭이 360px을 넘지 않습니다. "끝까지 플레이"는 1단계에서 확인합니다. |

### 접근성 기준 6개

| 기준 | 결과 | 근거 |
| --- | --- | --- |
| 색 대비, 색만으로 알리지 않기 | 통과 | 계층은 "L2"·"L3"·"L4" 글자, 결과는 도장 글자, 고른 카드는 "선택" 글자, 얻은 스티커는 "검수" 글자로 함께 알립니다. 대비 보완 3건은 5절에 적었습니다. |
| 누르는 영역 44×44px 이상 | 통과 | 4개 화면의 버튼과 링크를 모두 측정했고, 44px보다 작은 요소가 없습니다 (기본 높이 48px). |
| 드래그 없이도 플레이 | 1단계에서 확인 | 카드와 놓을 자리를 모두 `button`으로 만들어서 누르기와 키보드 조작이 가능한 구조로 그렸습니다. 실제 동작은 공통 틀에서 확인합니다. |
| 포커스 표시 | 통과 | Tab 키로 이동했을 때 컨베이어색 2px 외곽선이 표시됩니다. |
| 모달 포커스 가두기, Esc로 닫기 | 1단계에서 확인 | 시안은 정적 화면입니다. 구현에서는 `<dialog>`를 씁니다 (계획서 3.7절). |
| 200% 확대 | 통과 | 1280px 화면을 200% 확대한 것과 같은 640px 폭에서 4개 화면 모두 가로로 넘치지 않습니다. |

## 3. 토큰 규칙의 예외

시안 CSS에서 `tokens.css`에 없는 값을 쓴 곳은 아래 3종뿐입니다.

1. **토큰에서 계산한 값 4개**: `--line`(2px, `--space-1`의 절반), `--size-touch`(48px), `--width-page`(1152px), `--width-text`(40em). `mockups.css` 맨 위에 모아 두었습니다.
2. **화면 폭 조건 2개**: `@media`의 1040px, 860px. CSS 문법상 `@media` 안에는 토큰을 쓸 수 없습니다.
3. **색·간격·글꼴이 아닌 값**: 도장 기울기 6도, 줄 간격(1.2~1.6), 상자와 모달의 최대 폭(30em, 38em), 모달 뒤를 덮는 색의 혼합 비율(잉크 60%).

## 4. 결정이 필요한 사항

| # | 내용 | 추천 |
| --- | --- | --- |
| A | 휴대폰 스테이지 첫 화면에서 게임판이 약 130px만 보입니다. 작업 지시서(약 240px)와 부품 트레이(246px)가 화면을 나눠 쓰기 때문입니다. | 휴대폰에서는 작업 지시서를 제목 한 줄로 접고 "목표 보기"를 누르면 펼치도록 바꿉니다. 그러면 게임판이 약 280px 보입니다. |
| B | 월드맵 화면 제목 "네트워크 물류 센터 안내도"는 임시로 지은 이름입니다. PRD에 게임 이름이 없습니다. | 게임 이름을 정해서 알려 주세요. |
| C | 3절의 계산한 값 4개를 `tokens.css`에 넣을지 정해야 합니다. | 넣습니다. 넣으면 PRD의 토큰 코드에도 같은 줄을 추가합니다. |
| D | 반송 화면에 PRD에 없는 "붙인 L2 이더넷 헤더" 기록지를 추가했습니다. 플레이어가 실제로 붙인 주소를 보여 줘서 실패 이유를 확인하게 하려는 것입니다. | 유지합니다. 정답 주소는 보여 주지 않습니다. |
| E | 부품 트레이 카드가 3장이면 휴대폰에서 246px이고, 4장 이상이면 화면의 절반 가까이를 가립니다. | 스테이지 데이터에서 트레이 카드를 한 번에 3장 이하로 제한합니다. |

## 5. 시안을 만들면서 찾아 고친 문제

| 문제 | 조치 |
| --- | --- |
| 테이프색 L3 계층 띠가 흰 운송장과 구분되지 않음 (1.6:1) | 띠와 본문 사이에 잉크 선을 긋고, 띠 글자는 잉크색으로 씀 |
| 컨베이어색 포커스 외곽선이 상자색 위에서 보이지 않음 (1.9:1) | 상자 안의 요소는 외곽선을 요소 안쪽에 그림 (흰 면 5.9:1, 테이프색 면 3.7:1) |
| 테이프색 DropZone이 바닥과 구분되지 않음 (1.3:1) | 강조 상태에서도 점선 잉크 테두리를 유지함 |
| 상자의 라벨이 안쪽 것이 위로 겹쳐 보임 | 바깥 헤더가 위에 오도록 겹침 순서를 정함 |
| 휴대폰에서 상자 라벨이 아래에 붙은 부품 트레이 위로 올라옴 | 라벨의 겹침 순서를 상자 안에 가둠 (`isolation`) |
| 휴대폰에서 부품 트레이 높이가 304px (화면의 41%) | 카드 안쪽 여백을 줄이고 "선택" 표시를 계층 띠 안으로 옮겨서 246px로 줄임 |

## 6. PRD 컴포넌트 표와 다르게 그린 부분

- **월드맵 장소 배치**: 카드 4장이 한 줄로 늘어선 모습을 피하려고, 장소 표지판을 컨베이어의 위와 아래에 번갈아 붙였습니다. 휴대폰에서는 컨베이어가 왼쪽에 세로로 흐르고 표지판이 오른쪽에 쌓입니다.
- **StarRating**: 얻은 스티커 칸에 "검수" 글자를 넣었습니다. 테이프색 면과 흰 면의 대비가 낮아서 색만으로는 구분되지 않기 때문입니다.
- **헤더 라벨의 선택 표시**: 테두리 색과 함께 계층 띠 안에 "선택" 글자를 넣었습니다.
- **스테이지 예시 주소**: MAC 주소는 `AA:AA:AA:00:00:0A`처럼 장비를 구분하기 쉬운 학습용 값으로 적었습니다. 형식은 실제 MAC 주소와 같습니다.
