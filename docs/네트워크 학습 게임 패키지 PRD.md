# 네트워크 학습 게임 패키지 PRD

Nov 10, 2026 · @oreeyo

## 개요

네트워크 이론을 외우지 않고, 게임 규칙을 이해해야 이길 수 있는 4개 챕터로 몸에 익히는 웹 게임을 만든다.

**배경**

- OSI 계층, 서브넷팅, 포트·프로토콜은 암기 위주로 공부하면 지루하고 금방 잊는다.
- 네트워크는 "패킷이 어떤 규칙으로 어디를 거쳐 가는가"라는 시스템이라 게임 규칙으로 옮기기 쉽다.

**목표**

1. 네 가지 핵심 주제(캡슐화, 서브넷, 방화벽 룰, 장애 진단)를 플레이로 익힌다.
2. 챕터 순서가 곧 학습 순서가 되도록 구성한다.
3. 코드는 처음 보는 사람도 읽을 수 있을 만큼 쉽게 작성한다.

**대상 사용자**

- 1차: 본인 (네트워크 기초를 다지고 보안 엔지니어로 넘어가려는 개발자)
- 2차: 네트워크 입문자인 팀원·동료 (링크로 공유)

**핵심 원칙**: 퀴즈 맞히기에 점수를 주는 구조가 아니라, 개념을 모르면 스테이지를 깰 수 없는 구조로 만든다.

## 챕터별 상세

챕터마다 스테이지 5개로 시작하고, 앞 스테이지에서 배운 규칙을 다음 스테이지가 그대로 사용한다.

### 챕터 1. 패킷 택배 (캡슐화)

- **학습 목표**: 계층별 헤더의 역할, 캡슐화·역캡슐화 순서, 구간마다 MAC은 바뀌고 IP는 유지되는 이유
- **규칙**: 보낼 데이터에 헤더 카드(L4 TCP/UDP, L3 IP, L2 이더넷)를 순서대로 드래그해 붙인다. 라우터를 지날 때마다 L2 헤더를 새로 붙여야 한다. 받는 쪽에서는 바깥부터 벗긴다.
- **실패 조건**: 순서가 틀리거나, 라우터를 지난 뒤 이전 MAC을 그대로 쓰면 패킷이 반송된다.
- **스테이지 예시**
  1. 같은 네트워크 안의 PC에게 보내기 (헤더 3장)
  2. 라우터 1대를 거쳐 보내기 (MAC 교체 처음 등장)
  3. TCP와 UDP 중 맞는 것을 골라 보내기 (영상 통화 vs 파일 전송)
  4. 라우터 2대를 거쳐 웹 서버까지 보내기
  5. 도착한 패킷을 역캡슐화해서 원래 데이터 꺼내기

### 챕터 2. 서브넷 퍼즐 (IP 주소와 네트워크 범위)

- **학습 목표**: CIDR 표기, 서브넷 마스크, 네트워크·브로드캐스트 주소, 사용 가능한 호스트 수 계산
- **규칙**: 주어진 주소 블록을 요구 조건에 맞게 나눈다. 칸(주소 범위)을 블록처럼 쪼개고 각 부서에 배정한다.
- **실패 조건**: 호스트가 모자라거나, 범위가 겹치거나, 블록 밖으로 나가면 실패
- **스테이지 예시**
  1. 주어진 IP가 어느 네트워크에 속하는지 맞히기
  2. /24를 똑같이 4개로 나누기
  3. 호스트 50대 네트워크 3개를 /24 안에 배치하기
  4. 크기가 다른 부서(100대, 50대, 20대) 배치하기 (VLSM)
  5. 두 PC가 같은 네트워크인지 판정해서 통신 가능 여부 고르기

### 챕터 3. 방화벽 디펜스 (포트, 프로토콜, 룰 순서)

- **학습 목표**: 출발지·목적지·포트·프로토콜로 트래픽을 구분하는 법, 위에서부터 먼저 맞는 룰이 적용되는 원리, 기본 차단(default deny)
- **규칙**: 트래픽이 파도처럼 들어온다. 웨이브 시작 전에 룰 목록을 작성하고 순서를 정한다. 공격 트래픽은 막고 정상 트래픽은 통과시켜야 한다.
- **실패 조건**: 공격이 서버에 닿거나, 정상 트래픽이 일정 개수 이상 막히면 실패
- **스테이지 예시**
  1. 웹(80, 443)만 허용하고 나머지 차단
  2. 관리자 IP에서만 SSH(22) 허용
  3. 룰 순서 때문에 차단이 안 되는 상황 고치기
  4. DNS(53)는 UDP·TCP 둘 다 필요한 상황 처리
  5. 내부에서 밖으로 나가는 수상한 트래픽 차단 (아웃바운드)

### 챕터 4. 장애 탐정 (계층별 장애 진단)

- **학습 목표**: 아래 계층부터 위로 확인하는 진단 순서, 각 도구(ping, nslookup, 포트 확인, 경로 추적)가 어느 계층을 확인하는지
- **규칙**: "웹이 안 열린다" 같은 사건이 주어진다. 조사 도구를 하나씩 사용해 단서를 모으고, 원인과 해당 계층을 지목한다. 도구 사용 횟수가 적을수록 높은 등급을 받는다.
- **실패 조건**: 원인을 잘못 지목하면 실패, 도구 사용 횟수 초과 시 실패
- **스테이지 예시**
  1. 케이블이 빠진 PC (L1)
  2. IP는 되는데 도메인으로 접속이 안 됨 (DNS)
  3. 서버는 살아 있는데 웹만 안 열림 (포트·방화벽)
  4. 같은 네트워크로 착각한 서브넷 설정 오류 (L3, 챕터 2 연계)
  5. 원인이 두 개 겹친 복합 사건

## 공통 기능

4개 챕터가 똑같은 틀을 쓰도록, 아래 기능은 챕터 1을 만들 때 한 번 만들고 나머지 챕터에서 재사용한다.

| 기능 | 내용 | 비고 |
| --- | --- | --- |
| 월드맵(허브) | 챕터 4개를 고르는 첫 화면, 잠긴 챕터와 진행률 표시 | 챕터 해금 규칙 반영 |
| 스테이지 선택 | 챕터 안의 스테이지 목록, 별점(1\~3개) 표시 |  |
| 진행도 저장 | 클리어한 스테이지와 별점을 브라우저에 저장, 새로고침해도 유지 | 서버 없음 |
| 개념 요약 카드 | 스테이지를 깨면 방금 쓴 개념을 3줄로 정리해서 보여 줌 | 도감 화면에서 다시 보기 |
| 개념 도감 | 지금까지 얻은 요약 카드 모음 (복습용) |  |
| 힌트 | 스테이지당 힌트 최대 2단계, 쓰면 별점 1개 감소 |  |
| 결과 화면 | 성공·실패, 별점, 실패 이유 설명, 다시 하기/다음 스테이지 | 실패 이유 설명이 핵심 |
| 튜토리얼 | 챕터 첫 진입 시 조작법 3단계 안내 | 건너뛰기 가능 |

**해금 규칙**: 챕터 1의 스테이지 5개를 모두 깨면 챕터 2가 열리는 식으로, 앞 챕터를 끝내야 다음 챕터가 열린다. 챕터 4(장애 탐정)는 앞의 세 챕터 내용을 모두 쓰기 때문이다.

**별점 기준**: 클리어 1개, 힌트 미사용 2개, 실수 없이 클리어(또는 도구 최소 사용) 3개.

## 개발 규칙

세 가지 규칙은 필수이며, 코드 리뷰 때 이 규칙을 어긴 코드는 고친 뒤에 합친다.

### 규칙 1. 무조건 쉬운 코드

목표는 "리액트를 막 배운 사람이 파일 하나를 열었을 때 위에서 아래로 읽으면 이해되는 코드"이다.

1. **짧은 함수**: 함수 하나는 한 가지 일만 하고, 30줄을 넘기면 나눈다.
2. **쉬운 이름**: 이름만 보고 하는 일을 알 수 있게 짓는다. 줄임말 금지 (`calcHosts` X, `calculateHostCount` O).
3. **한 줄에 한 동작**: 삼항 연산자 중첩, 긴 메서드 체이닝, 한 줄짜리 트릭 금지. 길어져도 `if`문으로 풀어 쓴다.
4. **기본 문법만 사용**: `useState`, `useEffect`, props, `map`, `filter` 수준에서 해결한다. 커스텀 훅, Context, 고급 패턴은 꼭 필요할 때만 쓰고, 쓸 때는 이유를 주석으로 남긴다.
5. **타입스크립트 미사용**: JavaScript로 작성한다. 학습 부담을 줄이기 위해서다.
6. **게임 규칙과 화면 분리**: 정답 판정·계산 같은 게임 규칙은 `rules/` 폴더의 순수 함수로 두고, 컴포넌트는 화면만 그린다. 규칙만 따로 읽고 테스트할 수 있게 하기 위해서다.
7. **스테이지 데이터는 파일로 분리**: 스테이지 내용은 코드에 섞지 않고 `data/` 폴더의 JS 객체로 둔다. 스테이지 추가 = 데이터 추가가 되도록 한다.
8. **주석은 "왜"를 쓴다**: 코드가 무엇을 하는지는 코드로 보이게 하고, 주석에는 왜 이렇게 했는지를 한국어로 쓴다. 네트워크 개념이 들어간 계산에는 개념 설명 주석을 단다.

```jsx
// 사용 가능한 호스트 수 = 2의 (32 - 프리픽스) 제곱 - 2
// 2를 빼는 이유: 네트워크 주소(맨 앞)와 브로드캐스트 주소(맨 뒤)는 PC에 줄 수 없다.
function calculateHostCount(prefix) {
  const totalAddresses = 2 ** (32 - prefix);
  return totalAddresses - 2;
}
```

### 규칙 2. 공통 컴포넌트 최대 공유

1. **두 번 쓰이면 공통으로 뺀다**: 같은 모양의 UI가 두 곳 이상에서 쓰이면 `components/common/`으로 옮긴다.
2. **챕터 폴더에는 그 챕터만의 것만**: 버튼, 카드, 모달, 결과 화면, 힌트 박스는 챕터 폴더에 만들지 않는다.
3. **스테이지 틀은 하나**: 모든 챕터의 스테이지는 공통 `StageLayout` 안에 챕터별 게임판만 끼워 넣는 구조로 만든다. 상단 바, 힌트, 결과 화면이 자동으로 같아진다.
4. **props로 차이를 표현**: 비슷한 컴포넌트를 복사해서 새로 만들지 않고, props(`variant`, `size` 등)로 모양 차이를 준다. 단, props가 6개를 넘으면 나누는 것을 검토한다.
5. **새 컴포넌트를 만들기 전에 공통 목록부터 확인**한다 (기술 스택 섹션의 공통 컴포넌트 목록).

### 규칙 3. 라이브러리 사용 이유 주석

1. 라이브러리를 `import`하는 줄 바로 위에 **왜 이 라이브러리를 골랐는지** 주석을 단다.
2. 주석에는 세 가지를 쓴다: 무엇을 하려고, 왜 직접 만들지 않았는지(또는 다른 라이브러리 대신 고른 이유), 어디에 쓰는지.
3. 같은 라이브러리를 여러 파일에서 쓰면, 처음 도입한 파일에 자세히 쓰고 나머지 파일에는 한 줄로 요약한다.
4. 새 라이브러리를 추가할 때는 이 문서의 기술 스택 표에도 이유를 한 줄 추가한다.

```jsx
// [라이브러리] @dnd-kit/core
// 왜: 챕터 1에서 헤더 카드를 드래그해서 패킷에 붙이는 기능이 필요하다.
//     브라우저 기본 드래그 기능은 모바일 터치에서 동작하지 않아서 직접 만들기 어렵다.
//     react-beautiful-dnd 대신 고른 이유: 개발이 중단되었고, dnd-kit이 더 가볍다.
// 어디에: DraggableCard, DropZone 공통 컴포넌트
import { DndContext } from '@dnd-kit/core';
```

## 디자인 가이드

화면은 '네트워크 물류 센터' 콘셉트 하나로 통일하고, 색·글꼴·모양은 토큰 파일에 정한 값만 쓴다. 개발 규칙과 똑같이 필수이다.

### 콘셉트: 네트워크 물류 센터

데이터는 택배 상자, 헤더는 상자에 붙이는 운송장 라벨로 그린다. 캡슐화가 실제로 상자에 라벨을 겹쳐 붙이는 일과 구조가 같아서, 비유가 개념을 왜곡하지 않는다.

| 화면 | 센터 안의 장소 | 화면에서 보이는 모습 |
| --- | --- | --- |
| 월드맵 | 센터 안내도 | 컨베이어 한 줄이 네 장소를 순서대로 잇는다 |
| 챕터 1. 패킷 택배 | 집하장 | 데이터는 상자, 헤더는 운송장 라벨, 라우터는 중간 분류장 |
| 챕터 2. 서브넷 퍼즐 | 주소 구획실 | 주소 블록은 바닥의 구역, 서브넷은 구역선 긋기 |
| 챕터 3. 방화벽 디펜스 | 검문소 | 룰은 검문 기준표, 트래픽은 컨베이어 위 상자 |
| 챕터 4. 장애 탐정 | 사고 조사실 | 사건은 배송 사고 접수증, 도구 결과는 조사 기록지 |
| 결과 화면 | 검수대 | 성공은 '통과' 도장, 실패는 '반송' 도장 |

**디자인 원칙**

1. **비유는 모양에만, 용어는 실제 그대로**: 운송장 모양이어도 글자는 "IP 헤더", "목적지 MAC"으로 쓴다. 비유가 실제 용어를 대신하면 학습 목표가 무너진다.
2. **힘은 게임판 한 곳에**: 상자, 라벨, 도장이 화면에서 가장 눈에 띄어야 한다. 목록, 메뉴, 설정 화면은 조용하게 둔다.
3. **장식 말고 정보**: 선, 색, 번호는 뜻이 있을 때만 쓴다. 번호는 실제 순서(스테이지, 계층)에만 붙인다.
4. **글꼴, 색, 도형만으로 개성을 만든다**: 캐릭터와 일러스트는 범위 밖이므로 쓰지 않는다.

처음에 후보였던 '귀여운 캐릭터풍'과 '해커 터미널풍'은 채택하지 않는다. 둘 다 학습 앱에서 가장 흔한 모습이라 구별되지 않는다.

### 색과 글꼴 (디자인 토큰)

색 9개와 글꼴 1개만 쓰고, 모든 값은 `src/styles/tokens.css` 한 파일에 둔다. 컴포넌트에는 색상 코드나 px 값을 직접 쓰지 않는다.

| 토큰 | 값 | 쓰는 곳 | 규칙 |
| --- | --- | --- | --- |
| 바닥 `--color-floor` | #E6E9EC | 화면 배경 | 차가운 회색. 크림색·검은색 배경 금지 |
| 라벨 `--color-label` | #FFFFFF | 운송장, 지시서, 모달 면 |  |
| 잉크 `--color-ink` | #16264A | 글자, 테두리 | 순검정 대신 남색 잉크 |

| 컨베이어 `--color-belt` | #1D5BD8 | 주 버튼, 선택 표시, 포커스 | 화면당 주 버튼 1개 |
| 테이프 `--color-tape` | #FFC21A | 지금 해야 할 일 한 곳 강조 | 글자색으로 금지, 잉크 테두리와 함께 |

| 반송 `--color-return` | #B42323 | 실패 도장, 차단 표시 | 글자·모양과 함께 |

| 역할 | 크기 | 굵기 |
| --- | --- | --- |
| 화면 제목, 도장 글자 | 32px | Black 900 |
| 챕터 이름, 스테이지 제목 | 24px | Bold 700 |
| 라벨 이름, 버튼 | 16px | SemiBold 600 |
| 본문, 설명 | 18px·16px | Regular 400 |
| 보조 설명, 계층 표시 | 14px | Regular 400 |

- 본문 줄 간격은 1.6, 한 줄은 한글 40자 이내로 한다.
- IP 주소, 포트 번호, 2진수는 자릿수가 세로로 맞도록 `font-variant-numeric: tabular-nums`를 켠다. 숫자용 글꼴을 따로 추가하지 않는다.
- Pretendard 한 가지만 쓰므로 제목과 본문의 차이는 굵기로 만든다. 제목은 Black 900, 본문은 Regular 400으로 굵기 차이를 크게 벌리고, 중간 굵기(500)는 쓰지 않는다. 다른 글꼴을 추가하지 않는다.

```css
/* src/styles/tokens.css
   색·글꼴·간격은 여기 값만 쓴다.
   이름은 물류 센터 콘셉트에서 가져왔다. (바닥, 라벨, 잉크, 컨베이어, 테이프, 상자) */
:root {
  /* 색 */

  --color-label: #FFFFFF;
  --color-ink: #16264A;
  --color-ink-quiet: #51607A;
  --color-belt: #1D5BD8;
  --color-tape: #FFC21A;
  --color-box: #B98A5E;
  --color-pass: #146C43;
  --color-return: #B42323;

  /* 글꼴 */
  --font-base: 'Pretendard Variable', Pretendard, sans-serif;
  --weight-title: 900;   /* 화면 제목, 도장 */
  --weight-strong: 700;  /* 챕터 이름 */
  --weight-label: 600;   /* 라벨 이름, 버튼 */
  --weight-body: 400;    /* 본문 */
  --text-xl: 32px;
  --text-lg: 24px;
  --text-md: 18px;
  --text-base: 16px;
  --text-sm: 14px;

  /* 간격: 4의 배수만 사용 */
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;
  --space-12: 48px;

  /* 모양 */
  --radius-label: 4px;  /* 운송장, 카드, 버튼 */
  --radius-panel: 8px;  /* 모달, 큰 영역 */
  --border-ink: 2px solid var(--color-ink);

  /* 토큰에서 계산한 값 (0단계 검수 기록 결정 C) */
  --line: calc(var(--space-1) / 2);          /* 2px: 선 굵기, 버튼이 눌리는 깊이 */
  --size-touch: var(--space-12);             /* 48px: 누르는 영역 (접근성 기준 44px 이상) */
  --width-page: calc(var(--space-12) * 24);  /* 1152px: 화면 최대 폭 */
  --width-text: 40em;                        /* 본문 한 줄은 한글 40자 이내 */
  /* 모달 뒤를 덮는 색. 새 색을 만들지 않고 잉크색과 바닥색을 섞는다. */
  --color-scrim: color-mix(in srgb, var(--color-ink) 60%, var(--color-floor));

  /* 움직임 */
```

### 화면 배치

월드맵은 카드 4장을 늘어놓지 않고 컨베이어 한 줄로 그리며, 스테이지 화면은 모든 챕터가 같은 세 단 구조를 쓴다.

&#91;embedded content: 화면 배치 · 월드맵과 스테이지 화면\]

- **월드맵**: 컨베이어가 왼쪽에서 오른쪽으로 네 장소를 잇는다. 휴대폰에서는 위에서 아래로 흐른다. 깬 챕터까지만 벨트가 컨베이어색으로 칠해진다.
- **스테이지 화면**: 위는 작업 지시서, 가운데는 작업대(게임판), 아래는 부품 트레이다. 공통 `StageLayout`이 이 세 단을 만들고 챕터는 작업대 안만 채운다.
- **정렬**: 제목과 본문은 왼쪽 정렬, 게임판 안의 상자와 도장만 가운데에 둔다.
- **휴대폰**: 세 단 구조를 그대로 유지하고, 부품 트레이는 화면 아래에 고정해 엄지로 닿게 한다.

### 컴포넌트 모양

공통 컴포넌트는 그림자 대신 잉크 테두리로 구분하고, 종류가 다르면 모양도 다르게 만든다.

| 컴포넌트 | 모양 | 상태 |
| --- | --- | --- |
| Button | 높이 48px, 모서리 4px. 주 버튼은 컨베이어색 면에 흰 글자, 보조 버튼은 흰 면에 잉크 테두리 | 누르면 2px 내려감, 비활성은 옅은 잉크 테두리와 글자 |
| Card (운송장) | 흰 면, 잉크 테두리 2px, 모서리 4px, 그림자 없음 | 선택되면 테두리가 컨베이어색 |
| 헤더 라벨 (DraggableCard) | 운송장 모양. 왼쪽에 계층 표시 띠와 "L2"·"L3"·"L4" 글자 | 끄는 동안 3도 기울고, 놓을 수 있는 자리는 점선 테두리 |
| 패킷 상자 | 상자색 면, 잉크 테두리 2px. 붙인 라벨이 겹쳐 쌓인다 | 라우터를 지나면 L2 라벨만 떼어진 자국이 남는다 |
| DropZone | 점선 잉크 테두리, 안에 놓을 것의 이름 | 카드가 위에 오면 테이프색 면 |
| ResultModal (검수대) | 흰 면, 모서리 8px. 왼쪽 위에 6도 기운 도장 | 통과는 통과색, 반송은 반송색 도장 |
| ProgressBar | 컨베이어 벨트 모양의 가로 막대, 칸이 스테이지 수만큼 나뉜다 | 깬 칸만 컨베이어색으로 채움 |
| StarRating | 별 대신 검수 스티커 3칸 | 얻은 칸만 테이프색으로 채움 |

계층 띠는 L4 컨베이어색, L3 테이프색, L2 잉크색으로 칠한다. 새 색을 추가하지 않고, 색과 함께 글자를 항상 표시한다.

### 움직임

움직임은 플레이어의 행동에 대한 대답으로만 쓰고, 눈에 띄는 연출은 결과 도장 하나뿐이다.

- **허용**: 버튼 누르기, 카드 집기와 놓기, 상자가 컨베이어를 따라 이동(게임 진행 표시), 결과 도장 찍기
- **결과 도장**: 위에서 내려와 찍히는 240ms 연출. 게임 전체에서 가장 큰 움직임이다.
- **금지**: 화면에 들어올 때 요소가 떠오르는 등장 효과, 모든 카드의 마우스 올림 확대, 계속 반복되는 배경 움직임
- 기기에서 '동작 줄이기'를 켠 사용자에게는 이동과 도장 연출을 끄고 결과만 바로 보여 준다 (`prefers-reduced-motion`).

### 문구

문구는 플레이어가 다음에 무엇을 해야 하는지 알려 주는 용도로만 쓰고, 말투는 짧은 해요체로 통일한다.

1. **버튼은 일어날 일을 말한다**: "확인", "제출" 대신 "패킷 보내기", "룰 적용하기"처럼 쓴다.
2. **실패 문구는 세 부분**: 무슨 일이 있었는지, 왜 그런지, 다음에 무엇을 할지 순서로 쓴다.
3. **같은 것은 같은 이름으로**: 챕터, 스테이지, 힌트, 별점, 개념 카드라는 이름을 모든 화면에서 똑같이 쓴다.
4. **과한 칭찬과 이모지 금지**: "대단해요!" 대신 무엇을 잘했는지를 쓴다.

| 상황 | 이렇게 쓴다 | 이렇게 쓰지 않는다 |
| --- | --- | --- |
| 챕터 1 실패 | 패킷이 반송됐어요. 라우터를 지났는데 이전 구간의 MAC 주소가 그대로예요. L2 헤더를 새로 붙여 보세요. | 오답입니다. 다시 시도하세요. |
| 챕터 1 성공 | 배송 완료. 헤더를 L4, L3, L2 순서로 붙였어요. | 정답입니다! 대단해요! |
| 챕터 2 실패 | 구역이 겹쳤어요. 두 서브넷이 192.168.0.64부터 같은 주소를 쓰고 있어요. 한쪽 구역선을 옮겨 보세요. | 잘못된 입력입니다. |
| 잠긴 챕터 | 아직 닫혀 있어요. 챕터 1의 스테이지 5개를 모두 깨면 열려요. | 잠김 |
| 힌트 버튼 | 힌트 보기 (별점 1개 감소) | 힌트 |
| 진행도 초기화 | 진행도를 모두 지울까요? 별점과 개념 카드가 사라지고 되돌릴 수 없어요. \[모두 지우기\] \[그대로 두기\] | 정말 삭제하시겠습니까? \[확인\] \[취소\] |

### 금지 목록

아래 항목은 AI가 만든 화면에서 반복되는 모습이라, 코드 리뷰에서 발견되면 고친 뒤에 합친다.

- 보라·파랑 그라데이션 배경, 그라데이션 글자
- 모든 카드에 똑같은 둥근 모서리와 옅은 회색 그림자
- 검은 배경에 형광 초록(해커 터미널), 크림색 배경에 주황 강조
- 유리처럼 비치는 흐림 효과, 네온 빛 번짐
- 이모지를 아이콘으로 쓰기
- 제목 위의 작은 영문 대문자 라벨, 제목에서 한 단어만 색 바꾸기
- 버튼 글자 뒤의 화살표(→)
- 순서가 아닌 내용에 붙인 01·02·03 번호 장식
- 화면 진입 시 떠오르는 등장 효과, 모든 카드의 마우스 올림 확대
- 토큰 파일에 없는 색, 간격, 글꼴 값을 컴포넌트에 직접 쓰기

### 접근성 기준

색 조합은 모두 WCAG 2.1 AA 기준(글자 4.5:1, 도형 3:1)을 넘는 것만 쓴다. 아래 대비는 계산해서 확인한 값이다.

| 글자·도형 | 배경 | 대비 | 기준 | 결과 |
| --- | --- | --- | --- | --- |
| 잉크 | 라벨(흰색) | 14.9:1 | 4.5:1 | 통과 |
| 잉크 | 바닥 | 12.2:1 | 4.5:1 | 통과 |
| 옅은 잉크 | 바닥 | 5.2:1 | 4.5:1 | 통과 |
| 흰 글자 | 컨베이어(주 버튼) | 5.9:1 | 4.5:1 | 통과 |
| 잉크 | 테이프 | 9.2:1 | 4.5:1 | 통과 |
| 잉크 | 상자 | 4.9:1 | 4.5:1 | 통과 |
| 통과색 | 바닥 | 5.3:1 | 4.5:1 | 통과 |
| 반송색 | 바닥 | 5.4:1 | 4.5:1 | 통과 |
| 테이프 | 라벨(흰색) | 1.6:1 | 4.5:1 | 글자색 사용 금지 |
| 상자 | 바닥 | 2.5:1 | 3:1 | 잉크 테두리 필수 |

1. **색만으로 알리지 않는다**: 통과와 반송은 도장 글자로, 계층은 "L2"·"L3"·"L4" 글자로 함께 알린다.
2. **누르는 영역은 44×44px 이상**으로 만든다.
3. **드래그 없이도 플레이할 수 있어야 한다**: 카드를 눌러 고른 뒤 놓을 자리를 누르는 방식을 함께 지원하고, 키보드(Tab, Enter, Space)로도 같은 동작이 되어야 한다.
4. **포커스 표시**: 키보드로 이동한 요소에 컨베이어색 2px 외곽선을 표시한다.
5. **모달**: 열려 있는 동안 포커스가 모달 안에 머물고, Esc로 닫힌다.
6. 브라우저를 200%로 확대해도 화면이 깨지지 않아야 한다.

### 화면 검수 절차

규칙을 적어 두는 것만으로는 결과가 보장되지 않으므로, 코딩 전에 시안을 확정하고 실제 화면을 시안과 비교한다.

1. **코딩 전**: 월드맵, 챕터 1 스테이지, 결과 화면 3장을 시안으로 먼저 만들어 확정한다.
2. **공통 틀 완성 직후**: PC와 휴대폰 화면을 캡처해 시안과 나란히 놓고 비교한다.
3. **챕터를 추가할 때마다** 같은 비교를 반복한다.

검수할 때는 아래 항목을 확인한다.

- [ ] 게임 이름을 가려도 다른 학습 앱과 구별된다.
- [ ] 화면에서 가장 먼저 눈에 들어오는 것이 게임판이다.
- [ ] 금지 목록에 해당하는 요소가 없다.
- [ ] 컴포넌트에 토큰 파일에 없는 색, 간격, 글꼴 값이 없다.
- [ ] 접근성 기준 6개를 모두 지킨다.
- [ ] 휴대폰 화면(가로 360px)에서 가로 스크롤 없이 끝까지 플레이된다.

## 기술 스택과 폴더 구조

React(JavaScript) + Vite로 만들고, 라이브러리는 꼭 필요한 2개만 추가한다. 서버 없이 정적 사이트로 배포한다.

### 기술 스택

| 항목 | 선택 | 고른 이유 |
| --- | --- | --- |
| UI | React (JavaScript) | 화면이 많고 진행도를 공유하므로 컴포넌트로 나눠 관리하기 쉽다. 리액트 연습도 겸한다. |
| 빌드 도구 | Vite | 설정 없이 바로 시작할 수 있고 저장하면 화면이 즉시 바뀐다. |
| 화면 이동 | React Router | 월드맵 → 챕터 → 스테이지마다 주소가 생겨 뒤로가기와 새로고침이 자연스럽다. |
| 드래그 앤 드롭 | @dnd-kit/core | 헤더 카드·주소 블록 드래그에 필요하고, 모바일 터치를 지원한다. |
| 스타일 | CSS Modules | 별도 라이브러리 없이 Vite에 기본 포함되고, 클래스 이름이 컴포넌트끼리 섞이지 않는다. 색·글꼴·간격 값은 tokens.css의 토큰만 쓴다. |
| 애니메이션 | CSS transition | 패킷 이동 정도는 CSS로 충분해서 라이브러리를 추가하지 않는다. |
| 진행도 저장 | localStorage | 서버 없이 브라우저에 저장한다. 읽기·쓰기는 `utils/storage.js` 한 곳에서만 한다. |
| 배포 | 정적 호스팅 (Vercel 등) | 빌드 결과만 올리면 링크로 공유할 수 있다. |
| 규칙 테스트 (개발용) | Vitest | `rules/`의 순수 함수를 화면 없이 테스트한다. Vite와 설정을 공유해서 추가 설정이 거의 없다. 개발 의존성이라 배포 결과물에는 들어가지 않는다 (계획서 D3). |
| 코드 검사 (개발용) | ESLint (+ eslint-plugin-react, eslint-plugin-react-hooks, globals) | 함수 30줄, 삼항 연산자 중첩 금지를 사람 대신 도구가 확인한다. 개발 의존성이라 배포 결과물에는 들어가지 않는다. |

## 개발 단계, 범위 밖, 성공 기준

공통 틀과 챕터 1을 먼저 끝까지 완성해 재미와 학습 효과를 확인한 뒤, 나머지 챕터를 하나씩 추가한다.

### 개발 단계

1. **공통 틀**: 화면 시안 3장 확정, 토큰 파일(tokens.css), 프로젝트 세팅, 월드맵, 스테이지 목록, StageLayout, ResultModal, 진행도 저장
2. **챕터 1 패킷 택배**: 스테이지 5개 + 개념 카드. 여기서 실제로 머리에 남는지 직접 플레이해서 확인한다.
3. **챕터 2 서브넷 퍼즐**: 공통 컴포넌트를 재사용하는지 점검하며 개발
4. **챕터 3 방화벽 디펜스**
5. **챕터 4 장애 탐정**: 앞 챕터 개념을 섞은 사건 구성
6. **마무리**: 개념 도감, 튜토리얼, 모바일 화면 점검, 배포

### 범위 밖 (이번 버전에서 하지 않음)

- 로그인, 서버, 다른 사람과 점수 비교 (랭킹)
- 실제 네트워크 장비나 패킷 캡처 연동
- 효과음·배경음악, 캐릭터 일러스트
- 다국어 지원

### 성공 기준

- [ ] 4개 챕터, 챕터당 스테이지 5개 이상을 플레이할 수 있다.
- [ ] 챕터를 깬 뒤 해당 개념(예: /26의 호스트 수, MAC이 바뀌는 이유)을 설명 없이 말할 수 있다.
- [ ] 공통 컴포넌트 목록 외에 챕터 폴더 안에 중복된 UI 컴포넌트가 없다.
- [ ] 모든 라이브러리 import 위에 사용 이유 주석이 있다.
- [ ] PC와 휴대폰 브라우저에서 모두 끝까지 플레이할 수 있다.
